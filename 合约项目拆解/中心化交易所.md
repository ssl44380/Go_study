## 二、各模块职责详解

### 1. `puller` — 订单生产者（数据入口）
**位置**: `puller/puller.go:57-67`

| 功能             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **职责**         | 从 MySQL 按 SeqId 递增拉取订单，喂给撮合引擎                 |
| **数据源**       | `aibit_spot_sequence_{symbol}` 表，每批 LIMIT 2000           |
| **关键循环**     | `GoPuller()` (puller/puller.go:132) 持续轮询，空轮询超过 50 次后才 sleep 1s |
| **订单类型映射** | DB 中 int32 → `match.Order` 的 Buy/Sell + Limit/Market/IOC/Fok 等 |
| **挂单校验**     | `CheckOrderScale()` 校验精度，不合规自动变 SystemCancel      |
| **输出通道**     | `chan *match.Order`，容量 5000                               |

### 2. `match` — 撮合引擎核心
**位置**: `match/order_book.go`, `match/matcher.go`

| 功能             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **数据结构**     | `OrderBook{ BuySet, SellSet *TreeSet, cache map[int64]*Order }` |
| **TreeSet**      | 用 `emirpasic/gods` 的有序集合，按价格/SeqId 排序，买卖双方各维护一棵 |
| **撮合主函数**   | `OrderBook.Match(order)` (matcher.go:231) 根据订单类型分发   |
| **6 种撮合策略** | `matchMarket`(市价)、`matchLimit`(限价，不成交挂单)、`matchIoc`(不成交撤单)、`matchFok`(预判断全成)、`matchCancel`(撤单)、`matchBatchCancel`(批量撤单) |
| **自成交保护**   | 同用户对手单相遇时，根据 Stp(CB/CO/CN/CAD/DAC) 策略处理      |
| **熔断保护**     | `CircuitRate` 参数，市场单撮合价格偏离首笔超过阈值 → CircuitCanceled |
| **输出结果**     | `MatchResultWithAskBid{ Mr, AskPrice, AskVol, BidPrice, BidVol }` 包含盘口快照 |
| **发布机制**     | `PublishResultChan()` (matcher.go:144) 批量聚合 90 条 → fanout 到 RabbitMQ |

### 3. `snapshotter` — 崩溃恢复
**位置**: `snapshotter/snapshotter.go`

| 功能           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| **为什么需要** | 内存中的 OrderBook 重启即丢，需要定期落盘做 checkpoint       |
| **序列化格式** | Gob（Go 原生二进制格式），文件命名 `{FromId:012d}.{symbol}-snapshot-go` |
| **原子写入**   | 写 TMP 文件 → `os.Rename()` 正式替换，避免 crash 时留下半写文件 |
| **S3 备份**    | 同时上传到 AWS S3（可开关），目录结构 `{app.seq}/{symbol}/`  |
| **历史清理**   | 最多保留 `n-history`(默认 10) 个快照文件                     |
| **恢复流程**   | `GetLastSnapshotId()` 扫描目录 → `Load()` gob 反序列化 → 重建 cache 索引 |
| **Clone 机制** | `OrderBook.Clone()` (order_book.go:199) 深拷贝，snapshot goroutine 与撮合 goroutine 解耦 |
| **快照触发**   | 定时任务（每 60s）或撮合线程发出 "snapshot!" 信号            |

### 4. `persistence` — 撮合结果落库
**位置**: `persistence/persistence.go`

| 功能             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **职责**         | 异步把 MatchResult 批量 INSERT 到 MySQL                      |
| **双缓冲设计**   | mrChan → mrBatchChan，先攒到 `batch-size`(30) 条再一次性拼 SQL |
| **多协程持久化** | `conn-num`(32) 个 goPersistence() 并发写                     |
| **有序写入**     | `insertSortMr()` 按 MatchResult.Id 排序后再拼接 SQL          |
| **落库表**       | `t_exchange_match_result_{symbol}`，字段: f_id/symbol/ts/order_type/role/mr/extra |

### 5. `l2quote` — 行情聚合（K线/Ticker/Trade）
**位置**: `l2quote/l2quote.go`

| 功能           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| **职责**       | 消费撮合结果，计算 9 种 K线 + 24h Market + Ticker + Trade    |
| **处理模型**   | 一条 mr 广播到 11 个 channel（每种行情一个 goroutine）并行处理 |
| **9 种 K线**   | 1min/5min/15min/30min/60min/4hour/1day/1week/1mon            |
| **K线存储**    | `treemap.Map` 按时间戳有序，每小时释放 >1440 根的陈旧数据    |
| **Redis 缓存** | `saveKlinesToRedis()` 每秒保存，客户端用 go-redis/v8         |
| **MQ 推送**    | 每 `mq-send-interval-ms`(500ms) 打包一次发 RabbitMQ          |
| **快照支持**   | 收到 "snapshot!" 信号时先 save redis → 再 takeSnapshot       |
| **去重保护**   | `MaxMRId` 记录已处理的最大 id，防止重启后重复处理            |

### 6. `market` — 深度行情
**位置**: `market/depth.go`, `market/thread.go`

| 功能             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **职责**         | 从 OrderBook 挂单构建聚合深度，发给下游                      |
| **多精度深度**   | 配置文件定义 12 个 depth-step，每个 step 一个 goroutine 并行计算 |
| **深度聚合**     | `orderDepth()` 按 price_step 精度 roundUp/roundDown 后同档 amount 累加 |
| **10% 容量深度** | `orderAccumulatedDepth()` 基于 midPrice 构建深度图专用，强制生成所有档位 |
| **触发时机**     | matcher 中 minDepthTicker(30ms) / default-update-interval(1000ms) / stackedTicker(1s) |
| **MQ 批量发送**  | `MarketThread.thread()` 批量聚合 depthChan → JSON 打包 → RabbitMQ |

### 7. `rabbitmq` — 消息总线
**位置**: `rabbitmq/rabbitmq.go`

| 功能              | 说明                                                         |
| ----------------- | ------------------------------------------------------------ |
| **连接池**        | 默认 10 个 RabbitMq 连接池（`conn-num: 10`），每个 symbol 分配一个连接 |
| **异步发送**      | 每个连接独立的 publishChan(10000)，Publisher 从 chan 取消息发 AMQP |
| **自动重连**      | 连接/Channel 断开时 reconnect 循环重试                       |
| **支持压缩**      | Zlib 压缩（可开关），ContentType 在 text/json 与 text/plain 间切换 |
| **监控指标**      | 每 10s 上报 chan 长度，每 60s 上报发布总数                   |
| **三种 Exchange** | match-result(撮合结果) / l2quote(深度行情) / ts-bumper(时间戳推进) |

### 8. `redis` — 缓存层
| 功能         | 说明                                                 |
| ------------ | ---------------------------------------------------- |
| **客户端**   | go-redis v8 连接池，支持集群模式（配置里留了多节点） |
| **存储内容** | K 线数据、行情缓存、撮合序列 ID 生成                 |

### 9. `scheduler` — 定时器
**位置**: `scheduler/scheduler.go`

| 功能                        | 说明                                                         |
| --------------------------- | ------------------------------------------------------------ |
| **设计意图**                | 替代裸 time.Ticker，支持 **固定时间点触发** + **可停止**     |
| **Snapshot Ticker**         | 配置 `[0, 60000]` 表示从第 0ms 开始每 60s，带 seqOffset 多实例错开 |
| **Orderbook Report Ticker** | 每 25 分钟上报一次订单簿状态                                 |
| **OMinuteBySecond**         | 每分钟第 N 秒触发（l2quote 用），处理边界对齐                |

## 三、完整数据流转时序

```
启动阶段:
  ┌─────────────────────────────────────────────────────────────────┐
  │ main() → Init()                                                 │
  │                                                                 │
  │  1. LoadConfigViper()    加载 YAML                              │
  │  2. snapshotter.Init()   初始化 S3 配置                          │
  │  3. snapshotter.GetLastSnapshotId() 找到最近一次快照              │
  │  4. snapshotter.Load()  恢复 OrderBook                          │
  │  5. puller.Init(ch, symbol, fromId+1) 从 MySQL 拉增量订单       │
  │  6. persistence.Init()   初始化结果落库                          │
  │  7. l2quote.NewL2quote() + Init() + Run()                       │
  │  8. MarketThreadInit() + startMatcher()                         │
  └─────────────────────────────────────────────────────────────────┘

运行阶段（一笔订单的完整旅程）:

  MySQL表 ──pullOrder()──▶ puller.ch ──▶ matcher goroutine ──▶ OrderBook.Match()
       │                                                        │
       │  每50ms轮询                                             │  6种撮合策略
       │                                                        │  自成交/熔断保护
       │                                                        │
       │                                        ┌───────────────┼───────────────────────┐
       │                                        ▼               ▼                       ▼
       │                                matchResult   cloneBook               "snapshot!"
       │                                │               │
       │                                │               │
       │                      ┌─────────┼──────────┐    │
       │                      ▼         ▼          ▼    ▼
       │                   rabbitmq   persistence  l2quote
       │                   fanout    INSERT 批   mrChan
       │                   广播MySQL  量落库     ──▶ 9种K线
       │                                         ──▶ Trade记录
       │                                         ──▶ Ticker更新
       │                                         ──▶ Redis缓存
       │                                         ──▶ RabbitMQ推送
       │
       │  同时（matcher 的定时 ticker）:
       │  OrderBook.Take(1800) ──▶ market.buildDepth() ──▶ depthChan ──▶ MarketThread
       │    12个 depth-step 并行计算                       ──▶ RabbitMQ 广播
       │
       │  同时（matcher 的定时 ticker）:
       │  snapshotter.C <- Clone() ──▶ dumpSnapshot() ──▶ gob encode ──▶ rename ──▶ S3
       │
       │  snapshotter 完成后发 "snapshot!" ──▶ l2quote 同步打行情快照

崩溃恢复:
  重启时: snapshotter.Load() 恢复 OrderBook 到 lastSnapshotId
  然后 puller 从 lastSnapshotId+1 继续从 MySQL 拉订单补撮合
  （snapshot 是 OrderBook 的 checkpoint，MySQL 是完整的订单流水）
```

## 四、设计亮点总结

| 设计                         | 实现                                                      | 为什么重要                            |
| ---------------------------- | --------------------------------------------------------- | ------------------------------------- |
| **单 symbol 单 goroutine**   | 每个交易对独立的 matcher goroutine + 独立 OrderBook       | 避免锁竞争，天然串行撮合保证顺序性    |
| **内存快照 + DB 流水双保险** | snapshotter 做 checkpoint，puller 从 MySQL 拉增量         | 毫秒级恢复，不丢单、不重撮合          |
| **Snapshot 异步 + Clone**    | `Clone()` 深拷贝在 matcher 中完成，快照 goroutine 只做 IO | 快照不阻塞撮合主循环                  |
| **批量异步落库/发 MQ**       | 所有下游操作都走 `chan → batch → flush` 模式              | 撮合引擎永不被外部 IO 反压            |
| **多精度深度并行**           | 12 个 depth-step 各开一个 goroutine 并行聚合              | 高频行情下也能 30ms 出深度            |
| **熔断 + 自成交双保护**      | CircuitRate + Stp(CB/CO/CN/DAC/CAD)                       | 金融级安全，防止市场操纵和自成交      |
| **多实例可部署**             | `app.seq` 配置实例偏移，snapshot 命名包含 seq，S3 分目录  | 横向扩展支持多 Captain（撮合实例）    |
| **OrderBook 用 TreeSet**     | 买卖盘各一棵有序树，按价格/SeqId 排序                     | O(log n) 找最优价挂单、O(1) Peek 对头 |
